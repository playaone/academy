## Semantic curriculum versioning

The curriculum uses:

```text
MAJOR.MINOR.PATCH
```

### MAJOR

Increment when a change alters the academy's fundamental direction or invalidates class numbering.

Examples:

- Reordering completed classes
- Replacing a major technology track
- Changing the primary capstone architecture
- Removing an entire phase

Completed classes should almost never be renumbered. Prefer a new major version with a migration note.

### MINOR

Increment when new planned material is added without invalidating completed work.

Examples:

- Adding a new module
- Adding new future classes
- Expanding a framework track
- Adding a new portfolio milestone

### PATCH

Increment for non-breaking corrections.

Examples:

- Correcting wording or typos
- Clarifying a prerequisite
- Refining an assignment
- Updating an outdated command without changing class intent

## Authority rules

1. The repository curriculum files are the primary source of truth.
2. Persistent assistant memory is a secondary index only.
3. Classes #001–#013 are learner-authoritative.
4. Class #014 onward is the reconstructed forward syllabus.
5. Missing historical content must not be invented and presented as recovered fact.
6. Every syllabus change must be recorded in `CHANGELOG.md`.
